# 7. How it works

## The rule that shapes everything

**Part-DB is not modified, and it is the only place where parts and stock live.** bom-agent keeps exactly one thing of its own: the intake queue (photos, notes, proposals) in a small SQLite database. Everything about parts — names, categories, quantities, boxes, attachments — is written to Part-DB through its REST API and read back from there.

Consequences:
- Part-DB upgrades are a tag change plus a migration; nothing to rebase.
- You can stop using bom-agent at any time; the inventory stays complete in Part-DB.
- Only one module, `bom_agent/partdb_client.py`, talks to Part-DB. A test (`tests/test_layering.py`) fails if another module tries.

## HTTP API (bom-agent)

The full list with request/response schemas is generated by FastAPI at `http://<server>:8091/docs`. The main routes:

| Route | Purpose |
|---|---|
| `GET /health` | service and Part-DB status; always HTTP 200, the state is in the body |
| `POST /api/intake/photo`, `POST /api/intake/voice` | add a photo / a typed list |
| `GET /api/intake` | the queue |
| `GET /api/intake/{id}/photo` | the photo (optionally `?crop=`) — this is the link stored in Part-DB |
| `GET /api/proposals`, `POST /api/proposals/{id}/…` | proposals: list, approve, reject |
| `GET /api/warsztat/snapshot` | the whole inventory as rows for the app (search happens in the browser) |
| `GET /api/warsztat/parts/{id}` | part card |

## Design decisions (and what was rejected)

**Recognition is done by the agent through MCP, not by a separate vision service.** A separate service would need its own API key, prompt and error handling, and could not ask "is this the bottom side of the previous module?". The agent already sees the photos, the existing categories and the inventory. *Rejected:* a vision microservice called on upload.

**Proposals before writes.** An unattended model writing directly into the inventory makes every mistake a cleanup job. A proposal costs one tap to reject. In a chat, the agent still commits directly — after showing a plan and getting a yes.

**Photos stay in bom-agent and Part-DB gets a link.** One copy of each photo, one place to back up. Catalogue pictures and datasheets from suppliers are the opposite: they are **downloaded** into Part-DB, because supplier links die within months and your parts stay in the box for years.

**A part's identity is its name, not its MPN.** Dozens of different modules share one chip (`TP4056`, `MAX7219`); matching by MPN merged different modules into one record. The MPN stays as information.

**Quantities as buckets.** Nobody counts 300 resistors from a photo. A model asked for a number invents one (100 one time, 500 the next). Buckets (*a few / quite a lot / lots*) plus Part-DB's "amount unknown" flag are honest.

**"Without a box" is a valid state.** During intake you often do not know yet where something will go. Forcing a box would mean random boxes; instead such parts land in a worklist.

**stdio MCP through `docker exec`, not an HTTP MCP endpoint.** No extra port, no extra token; access is whoever can run `docker` (or SSH in).

## Known pitfalls

- **Part-DB's `TRUSTED_HOSTS` is a regular expression** and an unknown `Host` header gets HTTP 400 *before* authentication — the error does not mention the token at all.
- **A fresh admin account has no API permission and must change its password** — until then the API returns 403 or redirects to the settings page (HTML instead of JSON).
- **Nested objects in a POST are refused** by Part-DB's API ("Nested documents … are not allowed") — create the part first, then its stock lot with the part's IRI.
- **Text search compares fragments**: "100n" does not find "100nF". That is why the agent ends descriptions of assortment boxes with a line `Szukaj:` ("search:") listing each value in several spellings.
- **Copying a live SQLite file** in WAL mode can produce a file that looks fine and cannot be opened — the backup uses Part-DB's own backup command and SQLite's backup API.
- **Cron has a minimal `PATH`**; the unattended script adds `~/.local/bin` itself so that `claude` is found.

```bash
uv sync --group dev
```
